<objective>
Land every change that is independent of the framework version *before* any version moves, so each later bump is a smaller step: harden the two library-mode build configs against Vite 6+ CSS-name derivation and Rollup 4's asset-name API, add a build-output assertion that makes the string contract loud instead of silent, declare the `terser` devDependency that `postBuild.js` already requires, and migrate the Svelte lint job from `eslint-plugin-svelte3` to `eslint-plugin-svelte@3`.

Purpose: RESEARCH Q1 and Q3 identify four ways this phase can fail *silently* — the CSS rename, the `assetInfo.name` throw, the a11y suppression, and a Svelte lint job that reports "0 problems" because it loads no rules. TOOL-03 forbids the last one outright, and TOOL-02 requires the single-CSS-asset rule to hold. Doing this work first means each subsequent version bump is verified against an already-correct build contract.

Output: a Vite build whose CSS name is deterministic, a `postbuild` chain that fails loudly on a broken contract, a declared `terser`, and a Svelte lint job on `eslint-plugin-svelte@3` that provably still performs the compiler check.
</objective>
