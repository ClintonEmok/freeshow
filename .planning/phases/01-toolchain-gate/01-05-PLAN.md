<objective>
Close TOOL-04: prove the packaged artifacts still build on Windows, macOS and Linux, and that the operator's path through the app still works on a packaged build with all three named native modules callable.

Purpose: this is the only phase criterion that cannot be satisfied on one machine. `build.yml` currently runs `npm ci` and `npm run build` and stops there — it never packages, so nothing in CI has ever produced an artifact with `electron-builder`. `ci.yml` and `playwright.yml` are both `workflow_dispatch`-only, so no badge means anything until a run is dispatched and its URL recorded. And `playwright.yml`'s virtual screen is `1280x960`, which would clamp a 1920x1080 output window on Linux and quietly make the pixel gate meaningless there.

Output: a `build.yml` that packs on all three platforms, a smoke spec that asserts the operator flow and exercises three native addons for real, an executed `RELEASE-SMOKE.md` with run URLs, and an honest statement of which claims rest on CI artifacts alone.
</objective>

        The flow, each step asserting its own observable outcome rather than assuming success:
        1. The real main window appears — poll `electronApp.windows().find((w) => w.url().includes("index.html"))` for up to 20 x 500 ms, with `firstWindow()` as fallback; guard the first-run Initialize popup with `if ((await setupStart.count()) > 0)`.
        2. Settings opens and renders — click the Settings entry point and assert a known Settings control is visible.
        3. An output window opens — trigger output creation and assert a page exists whose DOM matches `#output_window`. Do not select a window by index; `App.svelte:81` guarantees only the output branch renders `<MainOutput />`.
        4. A song plays — reuse the seeded show from `start.test.ts:107-114` and assert playback actually started (a playing state in the UI), not merely that a click landed.
        5. A file imports — mock `dialog.showOpenDialog` through `electronApp.evaluate` as `start.test.ts:22-26` does, and assert the import produced an observable result.

        **Native-module assertions, as a separate test in the same file.** Inside a single `electronApp.evaluate` block, require each module **and make it do work**. A bare `require` is explicitly rejected as evidence by `01-RESEARCH.md` row 5b, because requiring can be lazy and can succeed against a stub. Assert: `better-sqlite3` opens an in-memory database and returns a row from `select 1`; `@discordjs/opus` constructs an `OpusEncoder` at a real sample rate and channel count and reports a valid frame size; `osr-capture` exports a non-empty callable — and if `osr-capture` cannot be loaded, that is a **blocking TOOL-04 failure**, not a skip, because the criterion names it alongside the other two. Return a structured object per module (loaded, exercised, detail string) so a partial success is visible in the output rather than collapsing into one boolean.

        End the spec with `start.test.ts`'s shutdown guard (race `electronApp.close()` against a 5 s delay, `SIGKILL` a surviving process, remove both temp directories), so a hung Electron cannot wedge a CI matrix job.
